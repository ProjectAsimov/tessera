## Must do before release
1. Deploy the Tessera build of the PWA to https://projectasimov.github.io/tessera/ (currently the old TaskTracker build with `/tasktracker/` scope), in this order: D1 migration `worker/scripts/migrate.mjs --remote`, worker, PWA.
2. Add account deletion: an in-app "Delete account" control in `app/src/screens/Settings.tsx` calling a new worker route that removes users, tasks (hard delete including soft-deleted rows), entries, memberships (handle groups the user hosts), shoutouts and KV sessions; plus a public web deletion page (for example https://projectasimov.github.io/delete.html). Link both from the privacy policy and the Data safety form.
3. Add UGC safeguards: terms-of-use acceptance before creating or joining a group, an objectionable-content definition, an in-app Report for members and groups (a mailto to the support inbox is acceptable at this size, with a documented process), and a block or mute control for shoutouts and the leaderboard.
4. Update the privacy policy in the ProjectAsimov.github.io repo: add wallet (gems/freezes/milestones), per-day event counts, shoutouts, friend streaks and exactly what group members see; disclose Google Fonts (or self-host Inter); state retention and the web deletion link; fix the stale favicon URL. Add a visible Privacy policy link in the app (Settings and Welcome).
5. Refresh store assets: re-shoot screenshots from the Tessera build, re-export `store/feature-graphic.png` from the edited HTML, and correct `store/LISTING.md:15` to list what is actually collected (name, email, tasks and days, group data).
6. After the first upload, add the Play App Signing SHA-256 (Play Console, Setup, App signing) to the live `.well-known/assetlinks.json` next to the upload-key fingerprint, wait out the 10-minute Pages cache, and confirm the TWA opens with no URL bar on a tester device.
7. Console tasks: Data safety (types from the Results table, shared = No, encrypted in transit = Yes, deletion = in-app plus web link), IARC questionnaire (answers above), target audience 13+, ads = No, privacy policy URL, contact email, and add internal testers as Google OAuth test users (or publish the consent screen).

## Watch items (Needs action)
- Wallet is client-authoritative (`worker/src/routes/sync.ts:66-71`): fine while gems are earned-only; selling gems or freezes would require Play Billing and a server-authoritative balance.
- Rewarded ads, a coach subscription, push or a watch app each reopen Ads, Subscriptions, Notifications and Data safety (device tokens), plus a new IARC run.
- `android:allowBackup="true"` (`AndroidManifest.xml:90`): decide whether Android auto-backup of the TWA is intended; the policy says unsigned data stays only on the device.
- Group names come from free-text task names and are previewed publicly by invite code (`GET /groups/preview`); consider a length cap and the Report path from item 3.
- Support mailbox and Google Cloud project still carry the TaskTracker name; rename before publishing the OAuth consent screen.
- Re-check the current minimum target API in Play Console at upload (target 36 is set and very likely sufficient).
- Decide "gems" versus "tiles" before store copy mentions the currency.
- Back up the upload keystore and password (plain-text file, no other copy).
